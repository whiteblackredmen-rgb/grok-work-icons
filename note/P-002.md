## タイトル
止まらない自動化より、止まる自動化。留守のあいだに動くAIを「止まる向き」に作る手順

## 本文
自動化は、止まらないほど良い。じつは、これは逆です。

人が見ていない時間に動かす仕組みは、止まりやすいほうが安全です。

この記事を読むと、AIに任せた定時の仕事を「おかしいときは止まる」形に作り直せます。夜や早朝にAIを動かしている人、これから動かしたい人に向けて書きます。

この記事で手に入るものを、先に並べます。

無料の部分では、考え方を2つ説明します。

有料の部分には、そのまま使えるものを5つ置きました。

- 止まる条件を入れた、指示文（AIへの依頼の文章）のひな形
- 止まったときに残す、1行の記録の書式
- 翌朝に「届いたか」を確かめる、見張りの指示文
- 中身を問わない試運転の手順
- 実際に起きた失敗5つと、その直し方

数字や出来事は、この研究室の運用の記録にあるものだけを使います。

### 1. 「止まる」と「気づかない」を分けて考える

自動の仕組みで怖いのは、止まることではありません。止まったことに気づかないことです。

この研究室では、毎朝LINEに知らせを1通送る仕組みを動かしています。この知らせが、11月11日から届かなくなりました。気づいたのは、翌日の12日です。

別の例もあります。日曜の夜に自動で作るはずの下書きが、作られていませんでした。原因は、いまも確かめられていません。

どちらも、仕組みは止まっていました。害が出たのは、止まったからではありません。止まったという知らせが、どこにも出なかったからです。

ここから、作るときの決まりが1つ出てきます。

- 止まることは、許す。
- 黙って止まることは、許さない。

止まらない仕組みを目指すと、この区別が抜けます。止まらない前提で作るので、止まったときの知らせを用意しないからです。

### 2. 迷ったら「続ける」ではなく「見送る」を選ばせる

AIは、指示が足りないとき、気を利かせて先へ進もうとします。人が見ている昼間なら、それで助かります。留守のあいだは、これが事故のもとになります。

そこで、迷ったときの動きを、あらかじめ「見送る」に決めておきます。

記録にある例を3つ挙げます。

1つめ。送る前の文書に「要確認」という言葉が残っていました。仕組みは、それを見つけて、送る操作をしませんでした。記録には「できず」と、理由が1行残りました。

2つめ。文書の中の予告の日付が、実際の予定と食い違っていました。このときは「保留」にして、人の判断を待ちました。

3つめ。数字が届かなかった日、記録の係は「0」と書きませんでした。「数字なし」と書きました。0と書くと、測って0だったことになってしまうからです。

3つとも、仕事は進んでいません。そのかわり、まちがったものが外に出ることも、うその数字が残ることもありませんでした。

進まなかった仕事は、翌朝に人が進められます。まちがって出たものは、あとから戻せません。

留守のあいだの仕組みは、この差で考えます。進まない失敗は安く、進みすぎた失敗は高い。だから、止まる向きに倒しておきます。

ここまでが考え方です。ここから先は、指示文にどう書くかを、ひな形で示します。

### 3. 指示文に「止まる条件」を5つ足す

いま使っている指示文の末尾に、次の枠をそのまま足してください。〔 〕の中だけ、自分の仕事に合わせて書きかえます。

```
【止まる条件】次のどれかに当てはまったら、作業を進めずに終了する。
1. 材料が0件のとき。→ 何も作らず、すぐ終了する。
2. 材料や文書に「要確認」「未確認」「TBD」が残っているとき。→ その1件は見送る。
3. 日付・金額・あて先が、〔予定表のファイル名〕と食い違うとき。→ その1件は保留にする。
4. 今日すでに〔1日の上限の数〕件を済ませているとき。→ 残りは翌日に回す。
5. 使用量が〔80〕%を超えているとき。→ 今回は丸ごと見送る。

【してはいけないこと】
・足りない情報を、推測で埋めない。
・数字が取れなかったら「0」ではなく「数字なし」と書く。
・同じものを2回送らない。送ったら〔送信済みの記録ファイル名〕に1行足し、次回は先にそれを読む。

【人に聞くこと】次の4つに当たる場合だけ、進めずに質問を残して終了する。
個人が特定されること／アカウントの停止につながりそうなこと／お金が動くこと／他人への約束になること。
```

5つの条件は、どれも記録にある実例から取りました。

- 「0件なら即終了」は、材料集めの定時の仕事に入れている決まりです。
- 「要確認が残っていたら進めない」と「食い違ったら保留」は、2の例のとおりです。
- 「上限に達したら翌日へ」は、1日の上限に届いた晩に、残りの1本を翌晩へ回した例があります。
- 使用量の線は、80%で止める決まりと、70%以上で見送る決まりの、2つの例があります。どちらにするかは、自分の余裕で決めてください。

人に聞くことを4つに絞ったのにも、理由があります。聞くことが多いと、仕組みは毎晩止まります。毎晩止まる仕組みは、やがて使われなくなります。止まってほしい場面だけを、先に数えておきます。

### 4. 止まったら、1行だけ残させる

止まる条件を入れても、止まったことが見えなければ、1の失敗をくり返します。

そこで、動いた日も、止まった日も、同じ形の1行を残させます。指示文には、こう足します。

```
【記録】終わったら、〔記録ファイル名〕の末尾に、次の形で1行だけ足す。
日付｜仕事の名前｜済んだ数｜見送った数（理由）｜保留の数（理由）｜使用量
例：11/13｜朝の材料集め｜済 3｜見送り 2（要確認が残っていた）｜保留 0｜使用量 22%
何もしなかった日も、「済 0」で必ず1行足す。
```

大事なのは、最後の1文です。何もしなかった日にも、1行を書かせます。

こうすると、翌朝に見るものが1つに決まります。1行があって「済 0」なら、仕組みは動いたうえで見送っています。1行そのものが無ければ、仕組みが動いていません。この2つは、直し方がまったく違います。

知らせの出し方にも、記録にある決まりを1つ足しておきます。

- うまくいった日は、記録の1行だけ。知らせは送らない。
- 失敗した日だけ、知らせを1通送る。何件あっても1通にまとめる。

毎回「成功しました」と届く知らせは、やがて読まなくなります。読まなくなった知らせは、無いのと同じです。

### 5. 翌朝に「届いたか」を確かめる見張りを置く

仕組みが自分で「止まりました」と言えるのは、動いたときだけです。11月11日の朝の知らせのように、そもそも動かなかった日は、仕組みは何も言えません。

これを見つけるには、別の目が要ります。本体とは別の時刻に動く、小さな仕事を1つ足します。

```
あなたは見張りです。毎朝〔本体の30分あと〕に、次の1つだけを確かめてください。
1. 〔記録ファイル名〕の最後の行の日付が、今日かどうか。
2. 今日なら、何もせず終了する（知らせは送らない）。
3. 今日でなければ、「〔仕事の名前〕の今日の記録がありません」と1通だけ知らせて終了する。
原因を調べたり、本体の仕事を代わりにやり直したりは、しないでください。
```

最後の1文を、省かないでください。見張りに直させると、見張りが本体と同じまちがいをします。見張りの仕事は、気づくことだけにします。

この研究室で朝の知らせが止まったとき、気づいたのは翌日でした。見張りがあれば、その朝のうちに分かります。

### 6. わざと止めて試し、失敗の直し方を手元に置く

作った仕組みは、本番の前に1回、わざと止めてみます。

手順は4つです。

1. 中身はどうでもよい、試し用の材料を1件用意する。
2. その材料に、わざと「要確認」と1か所書きこむ。
3. 仕組みを1回動かす。
4. 記録に「見送り 1（要確認が残っていた）」の1行が出たかを見る。

記録には、こういう学びが残っています。試運転は「中身は問わない」と決めると、手順の失敗だけを確かめられる。

中身の出来まで同時に見ようとすると、どこが悪いのかが分からなくなります。止まるかどうかだけを、先に確かめます。

最後に、実際に起きた失敗5つと、その直し方を並べます。

- 朝の知らせが届かなくなり、翌日まで気づかなかった。→ 見張りを別の時刻に置く（5の見張り）。
- 日曜の夜の下書きが作られず、原因も分からない。→ 何もしなかった日も1行を残させる（4の記録）。原因を探す手がかりになります。
- 予告の日付と実際の予定が食い違い、保留にするしかなかった。→ 予告は、予定表を読ませてから書かせる。条件3の食い違いの確認を、書く前にも入れます。
- 数字が届かない日が続いた。→ 「0」と「数字なし」を書き分けさせる（3の枠）。届かなかった事実が、そのまま残ります。
- 同じ事実を何か所にも書かせたら、場所ごとに中身がずれた。→ 書く場所を1つに決め、ほかはそこを読ませる。

### まとめ

- 留守のあいだの仕組みは、止まることを許し、黙って止まることを許さない。
- 迷ったら「見送る」。進まない失敗は安く、進みすぎた失敗は高い。
- まず試すのは1つ。いまの指示文の末尾に、3の「止まる条件」の枠を足してください。
